# F01 — Modello dati, IndexedDB e comandi atomici

Data: 29 ottobre 2026. Ambiente: Windows / PowerShell, Node 26.13.0 e npm 11.20.0 portatili già predisposti in F00. Riferimento: commit F01 successivo a `9d9f942`.

## Implementato

- Tipi di dominio inferiti da schemi Zod strict: Procedure, Group, Revision Draft/Ready, Graph/Node/Outcome/Activity/Phase, Destination con quattro varianti, Settings, media/gallerie/Blob e RunSession.
- Dexie `NurseFlowDB`: sette tabelle, v1 conservata e upgrade v2 che aggiunge token mancanti senza eliminare dati. Default Settings/UI preferences soltanto alla prima creazione; nessuna fixture precaricata.
- Repository con valori separati e validati, factory pubblica senza tabelle o istanza Dexie esposta ai componenti.
- `createDraft`: nuova procedura oppure Draft indipendente da Ready-only; una Draft esistente viene riaperta. `updateDraft`: grafo e nuovi asset atomici con controllo di versione.
- `markReadyUnitOfWork`: rilettura della Draft durabile, token e consenso personale, validatore sincrono obbligatorio, nuova Ready immutabile e puntatore atomico. Nessuna modifica alla Ready precedente o alle run; la Draft rimane indipendente.
- `saveRun`: riferimento a una Ready propria, verifica dei riferimenti del progresso, pin/identità invariabili e controllo della versione del salvataggio.
- `addImportedRecords`: batch interni, nuove identità per tutte le entità e riferimenti, namespace separato per file/procedura, solo add/bulkAdd e transazione unica anche per più batch. Ready rimane Ready dopo validazione; Draft rimane Draft. Settings non sono accettate.
- W07 conserva un nuovo riferimento a media assenti senza inventare Blob; W08 conserva la destinazione broken e l'identità storica del nodo eliminato. Copie di gruppi omonimi restano distinte; layout, warning, revisioni pinnate e progressi AND sono remappati.
- Immutabilità Ready/asset protetta anche da hook Dexie. Nessuna GC; nessun file I/O, fetch o crypto asincrona nelle transazioni. ID e timestamp generati prima delle unità atomiche.

File principali: `src/domain/model/`, `src/domain/portability/records.ts`, `src/storage/{db.ts,index.ts,commands/,migrations/,repositories/}`, `src/test/fixtures/domain.ts`, unit/integration test ed E2E storage. Documentazione: README e [ADR-002](../adr/002-domain-storage-transactions.md).

## Limiti verificati e confini

Il WebKit Windows installato rifiuta Blob in IndexedDB nel context privato standard di Playwright. Una riproduzione con sole API IndexedDB native ha restituito `UnknownError: Error preparing Blob/File data to be stored in object store` per Blob privato, ma successo per Blob nel profilo persistente e ArrayBuffer in entrambi. Gli E2E storage utilizzano quindi profili persistenti temporanei isolati per tutti e tre i browser, senza skip o modifiche al modello MediaAsset. I precedenti tentativi E2E con Blob nel context privato WebKit sono falliti e non sono conteggiati come PASS. Questo limite non autorizza a dichiarare supporto generale alla navigazione privata.

- Validator concreto P01–P12/W01–W08: **F08**, non implementato in F01. Non è presente un default che approvi una Draft incompleta. I test iniettano esplicitamente un doppio di validazione escluso dalla build.
- Motore run e checkpoint canonici Back/redo: **F09**. F01 persiste lo scheletro minimo versionato, senza simulare la semantica OR/AND.
- Parsing/manifest/checksum/ZIP, preview e scope delle Pagine 11A/B: **F13/F14**. Nessun file non trusted viene accettato direttamente dal comando record; sostituzione Settings con consenso separato rimane F14.
- UI, stile e Pagine 00–11: nessuna modifica. La shell F00 non è ancora collegata ai servizi; nessun accesso Dexie nei componenti. Nessuna dichiarazione di prodotto pronto o di disponibilità offline dell'app shell.
- iOS Safari e Android Chrome su dispositivi fisici: **NON ESEGUITO**, dispositivi non disponibili. Playwright headless non sostituisce questi gate.
- Quota reale/eviction, installazione/cache PWA e multitab durante upgrade: **NON ESEGUITO**, fuori dai test simulati F01; hardening F15/F16.
- GitHub Actions e deploy remoto: **NON ESEGUITO**, nessun push/deploy richiesto o effettuato.
