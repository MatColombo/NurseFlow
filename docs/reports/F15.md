## Implementato

`vite-plugin-pwa` **2.0.0** e Workbox **7.4.1** fissati nel lockfile, compatibilità Vite 8 verificata. `injectManifest` compila il worker locale con manifest generato dai file effettivi, CSS e tutti i chunk compreso MapGraph. Precache massimo 2 MiB per asset, con errore build se superato. Nessun runtime CDN, tracker o caching obbligatorio di URL authored. Manifest standalone con id/start_url/scope derivati dalla stessa base del router; icone PNG locali 192/512, maskable con area sicura e touch icon 180. Nessuna registrazione in dev.

La registrazione production usa lo scope del repository. Settings dichiara “Pronta offline” soltanto con controller e verifica MessageChannel di tutte le entry precache; incompletezza, storage non disponibile e installazione fallita hanno messaggi e Retry. La cache è distinta dai dati/Blob Dexie e da un backup. About spiega primo accesso, media remoti, possibile rimozione dei dati e impossibilità di diagnosticare/recuperare con certezza un archivio vuoto. Non vengono aggiunti indicatori permanenti alle pagine congelate.

Aggiornamento prompt tramite servizio F12, Later/Update when idle. Protezione di run, Builder/Step Editor, nuova procedura e import/export, sessioni salvate, scritture e flush falliti. Prima di skipWaiting tutte le finestre nello scope devono confermare inattività; schede vecchie/non rispondenti o letture DB fallite bloccano l'operazione. Retry differito ogni cinque secondi finché il consenso è pendente. Solo il richiedente ricarica dopo cambio controller e nuova verifica; nessun reload da un semplice evento controllerchange. Chiusura di una scheda durante il controllo è gestita senza considerarla automaticamente sicura.

Migrazioni: avvisi blocked/versionchange, chiusura della vecchia connessione e nessun riavvio automatico o reset distruttivo. Il messaggio conserva l'incertezza fra modifica/rimozione in altro contesto e invita a conservare testi non salvati. Test in due tab reali: connessione v1 trattiene intenzionalmente l'upgrade, v5 attende, poi migra dopo chiusura; verifica token/versioni, Ready, procedure e preferenze. Un successivo schema v6 **solo fixture** forza versionchange, confronta record e dimostra chiusura senza reload. Il DB applicativo resta v5.

Workflow Pages: pubblica l'artefatto CI, permissions contents/read + pages/write + id-token/write, poi avvia Chromium sul vero `page_url` per verificare HTTPS, manifest/base/icone, cache controllata e reload offline. Aggiunto `tooling/pages-smoke.mjs`, disponibile anche a mano. Timeout CI aumentato per la suite cresciuta nelle fasi precedenti. Versioni Actions verificate sui release tag ufficiali; actionlint eseguito. Non è attestata un'esecuzione Actions remota.

## Limiti e gate aperti

Nessuna installazione/riapertura da icona o quota/eviction OS è stata osservata su iOS/Android fisici. La rimozione volontaria della cache non simula tutte le politiche OS. Il protocollo distingue limiti misurati su Windows da comportamenti documentati di iOS/Android, senza dichiarare quote o tempi di conservazione misurati. [WebKit](https://webkit.org/blog/14403/updates-to-storage-policy/) documenta quote/eviction e [web.dev](https://web.dev/learn/pwa/installation) differenze d'installazione; non sostituiscono la prova mobile.

`npm ci` segnala **21 advisory dev/build** (2 low, 19 moderate, inclusi tool preesistenti e transitivi Workbox), nessun high/critical; runtime audit zero. Non applicati downgrade/force proposti da npm che cambierebbero toolchain/API. Warning build >500 kB già presente e deprecazione inlineDynamicImports dal plugin PWA; bundle e worker restano locali precache. Rivalutare la toolchain nel gate sicurezza F16.

Alla consegna dell'implementazione locale il repository non aveva remote; GitHub CLI e dispositivi adb/Xcode non erano disponibili. Richiesto URL del repository di destinazione per completare pubblicazione e smoke, senza inventare un host. Il codice e le prove locali F15 erano reviewabili, con exit gate F15/G3/G5 aperti per installazione mobile e deploy reale. La pubblicazione successiva è registrata sotto; le prove su hardware mobile restano richieste prima di chiudere G3/F16.
